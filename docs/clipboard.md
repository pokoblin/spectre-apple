# 剪贴板

照 `third_party/ghost/docs/spec/gdp-spec.md` §7.9（以及 §6.5、§6.7 和安全一节的 "Privacy of the session"）自行实现。只用了 libgdp（MIT）里 `clipboard.hpp` 的常量（capability 名、`text/plain`、长度上限），回声抑制自己写（原因见下）。没有读过、也没有移植上游 `client/spectre` 的代码（GPL-3.0）。

## 分层

```
App/Shared/ContentView            工具栏：Clipboard 开关；iOS 上是菜单 + 系统的粘贴按钮
App/Shared/PlaybackModel          每个会话提供 `clipboard`；connect 时创建 ClipboardSync，Accept 里生效后 start()
  └ SpectreKit/Clipboard
      ├ ClipboardSync             一个会话的同步：开关、监视本地 changeCount、写入 host 的文本
      ├ ClipboardEchoFilter       回声抑制：记住“两边都认为持有”的那一段文本
      └ SystemPasteboard          NSPasteboard.general / UIPasteboard.general
  └ SpectreKit.RemoteSession      onClipboardText（会话队列）
      └ GDPKit.GDPSession         handlers.clipboardText、sendClipboardText(_:)；丢掉不合法的 UTF-8
          └ gdpcore::SessionClient  校验 MIME、空内容、长度；只在 `clipboard` 生效时收发
```

## 对照规范

| 规范 | 实现 |
|---|---|
| §6.7 capability | 两种来源（远端、loopback）都在 SessionHello 里提供 `clipboard`。Accept 里生效了才开始监视本地剪贴板，工具栏也才显示开关；host 不支持时什么都不发 |
| §7.9 只有 `text/plain` | 收到其他 MIME 的直接丢掉；发出的一律是 `text/plain` |
| §7.9 空内容、超过 1 047 552 字节 | 两个方向都丢弃，C++ 层和 Swift 层（`ClipboardEchoFilter`，按 UTF-8 字节数算）各查一次。本地剪贴板里没有可读文本（比如复制的是图片）就什么都不发，不会“清空” host 的剪贴板 |
| §7.9 UTF-8 | `GDPSession` 用 `String(validating:as: UTF8.self)` 解码，不合法的丢掉，不做替换字符 |
| §7.9 Accept 之后 host 发一次自己的剪贴板 | `ClipboardSync` 在 connect 时就创建好，不等 Accept：host 的剪贴板紧跟在 Accept 后面到，两个回调各自经 `Task { @MainActor }` 切到主线程，顺序没有保证 |
| §7.9 客户端连上时不能发自己的剪贴板 | 创建时、`start()` 时、打开开关时都把当前的 `changeCount` 记为基线，之前已经在剪贴板里的内容不会发出 |
| §7.9 不能把刚收到的文本再发回去 | `ClipboardEchoFilter`（见下）；另外写入之后马上把新的 `changeCount` 记为已看过 |
| §7.9 只同步 clipboard，不同步 primary selection | Apple 平台没有 primary selection |
| Privacy：SHOULD 让用户能关掉 | 工具栏的 Clipboard 开关，**默认关**，记在 UserDefaults 的 `clipboardSync` 里。关掉之后 host 发来的也不写入；capability 照样提供，所以会话中途打开会立即生效，不用重连 |

## 回声抑制：和 libgdp 的 `ClipboardEcho` 不同

libgdp 的 `ClipboardEcho` 分别记住“上次发出的”和“上次写入的”，两者都拒绝发送。这样有一个漏洞：

1. 本地复制 A → 发出，`last_sent = A`
2. host 上复制 B → 写入本地，`last_applied = B`
3. 本地再复制一次 A → `should_send(A)`：A 等于 `last_sent`，**不发**

结果 host 一直停在 B，而用户以为两边都是 A。`ClipboardEchoFilter` 只记一段文本 `synced`：上一次发出或写入的内容，也就是“两边都认为持有”的内容。本地变化等于它就不发，host 发来的等于它就不写，其他情况都照常收发并更新它。上面第 3 步里 A ≠ B，所以会发出。wraith 用的是 libgdp 的规则，所以反过来的情况（host 那边先发 A、收到 B、再复制 A）仍然会被 host 吞掉，这要等上游修复。

两边同时复制时，各自会把对方的写入当成新内容，最后可能不一致。规范没有定义冲突怎么解决，这里也不做处理。

## macOS

- **检测**：`NSPasteboard` 没有变化通知，只能比较 `changeCount`（一个整数，读它不会读内容）。时机：App 变为活跃时检查一次，在前台期间每 0.5 秒检查一次。**在后台不检查**：在别的 App 里复制的内容，要等切回 Spectre 才会发出，用户没打算粘贴到远端的东西就不会离开本机。App Nap 已经被会话的 activity 关掉（见 `PlaybackModel`），计时器不会被节流。
- **不发的内容**：带有 nspasteboard.org 约定类型 `org.nspasteboard.ConcealedType`（密码管理器复制的密码）、`TransientType`、`AutoGeneratedType` 的内容一律不发。
- **写入**：`clearContents()` 加 `setString`。写入后系统剪贴板会经通用剪贴板（Universal Clipboard）同步到用户的其他设备，这和用户自己复制的效果一样。

## iOS / iPadOS

- **host → 本地**：直接写 `UIPasteboard.general.string`，写入不需要权限。
- **本地 → host**：iOS 16 起，读取“别的 App 复制的内容”会弹出系统的“允许粘贴”提示，除非用户在“设置 → App → Spectre → 从其他 App 粘贴”里选了“允许”。所以分成两种方式：
  - **粘贴按钮**（默认）：工具栏上 SwiftUI 的 `PasteButton`（即 `UIPasteControl`）。由用户点击、系统读取，不弹提示；读到的文本发给 host。之后在远端按 Ctrl+V 粘贴。
  - **自动发送**（菜单里的 “Send Copies Automatically”，默认关，记在 `clipboardSendsAutomatically` 里）：和 Mac 一样，变为活跃时检查一次，在前台期间每 0.5 秒检查一次 `changeCount`。`hasStrings` 和 `changeCount` 都不会触发提示，只有真正读取 `.string` 时才会。所以只有剪贴板确实变了、而且有文本时才读，提示最多弹一次。适合已经在设置里选了“允许”的用户。
- **为什么 iOS 也要轮询**：最初只监听 `didBecomeActive` 和 `UIPasteboard.changedNotification`。实测在模拟器里，Spectre 一直在前台时，从外部复制（`simctl pbcopy`）既不触发 `changedNotification`，也不会有 `didBecomeActive`。分屏（Split View）、通用剪贴板也是这种情况。
- **用户拒绝时**：`.string` 返回 nil，不会发出；这次变化已经记为看过，不会反复读取、反复弹提示。

## 测试

- **GDPKitTests**（新增 4 个，“Clipboard (§7.9)”）：Accept 之后收到 host 的剪贴板，Unicode 内容正确；`text/html`、空内容、超长 1 字节、不合法的 UTF-8 都被丢弃，恰好等于上限的被接受；任何一方没有 `clipboard` 时两个方向都不收发（用 Ping/Pong 来回一次，确认之前发的都已经到了）；客户端发出的到达 host，空的和超长的不发；host 记住 viewer 的文本，下一个 viewer 连上时收到。
- **SpectreKitTests**（新增 11 个）：`ClipboardEchoFilter` 的回声、上面那个“再复制一次 A”的场景、长度按 UTF-8 字节数计算、显式发送可以重复；`ClipboardSync` 配一个内存中的假剪贴板：会话前的内容不发且根本不读，host 的文本写入且不回发，带密码管理器标记的和非文本的不发，关闭时不收不发、重新打开不补发，手动模式下不读剪贴板，`start()` 之前和 `stop()` 之后不监视。设置用独立的 `UserDefaults(suiteName:)`，不碰真实的设置。

合入音频之后，macOS 上 GDPKit 57 个、SpectreKit 150 个测试全部通过；iPad 模拟器上是 57 个和 148 个。

## 实测

loopback 的测试 host 也支持 `clipboard`：记住 viewer 发来的文本，下一个 viewer 连上时发给它；启动参数 `--host-clipboard TEXT` 让它一开始就有剪贴板内容。每秒的日志里会打印 host 收到的内容（`host clipboard: "…"`），App 自己的收发只打印字节数（`clipboard: sent N bytes`、`clipboard: host sent N bytes`），不打印内容。

**macOS**（`--source loopback --host-clipboard "hello from the loopback host ✓"`）：

- 连上之后本机剪贴板就是 host 的文本（字节核对过，✓ 是 `e2 9c 93`）；
- 在后台用 `pbcopy` 复制：没有发出；切回 Spectre：立刻发出，host 收到 `"copied on the Mac 剪贴板\n"`；
- 保持在前台时复制：0.5 秒内发出；
- 带 `org.nspasteboard.ConcealedType` 的内容：没有发出；
- host 已经持有的文本再复制一次：不重发；
- 用工具栏关掉开关：UserDefaults 变为 false，复制的内容不发；再打开：关闭期间复制的不补发，之后复制的照常发出。

**iPad 模拟器**（iPad Pro 13-inch (M5)，iOS 27.0）：

- 连上之后模拟器剪贴板就是 host 的文本；
- 默认的手动模式：`simctl pbcopy` 复制后不会自动发出；点粘贴按钮后发出，host 收到 `"copied on the iPad 📋 剪贴板"`，33 字节；
- 打开自动发送、权限还是“询问”时：系统日志里 `pasted` 进程显示 “Paste requires user authorization. Prompting...”，但模拟器写 TCC 失败（“Error returned while setting TCC value to 'limited'”），结果按拒绝处理（“Paste denied silently”），屏幕上看不到提示。这是模拟器的问题，要在真机上确认提示；
- 在设置里把“从其他 App 粘贴”改成“允许”之后：Spectre 在前台时用 `simctl pbcopy` 复制，2 秒内自动发出（不弹提示）。

### 踩过的坑

- **`simctl pbcopy` 按当前 locale 解码 stdin**：在 locale 不是 UTF-8 的 shell 里，emoji 会被当成 Mac Roman 解码，模拟器剪贴板里存的本身就是乱码（`📋` 变成 `üìã`，28 字节）。要用 `LANG=en_US.UTF-8 xcrun simctl pbcopy …`。macOS 的 `pbcopy`/`pbpaste` 也是一样，核对字节要设 UTF-8 locale。
- **在模拟器里切到设置 App 再回来**：Spectre 在后台被挂起，loopback 会话因为空闲超时结束（“Timer expired”）。这是 iOS 进入后台后原本就有的行为，和剪贴板无关。
- **`#expect` 里不能调用 mutating 方法**（Swift Testing 的宏把表达式展开成闭包）：先把一串调用的结果收集到数组里，再比较整个数组。

## 没有做的

- 图片、富文本、文件：规范只定义了 `text/plain`。
- iOS 上点粘贴按钮后顺便替用户按 Ctrl+V：剪贴板走 control 流，按键走 input 流，两个流之间没有顺序保证，host 可能先收到按键。
- 真机上的粘贴提示、真实 wraith 上的往返，还没有测。
